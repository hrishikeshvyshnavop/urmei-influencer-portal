## Product rules the designs must follow

- **Components first (user, 2026-10-19): "every reusable thing should be created as a component".** Anything that appears more than once, or will be reused in a later flow or state (cards, tiles, banners, rows, toolbars, pickers, empty states), is built as a local component (or a component set, with variants for its states), never as a hand-built frame copied around.
  - **Before building:** search the file's components (`Components — Dev Handoff`, the working page, and `search_design_system`) and reuse a match.
  - **States:** use variants (`State=Empty / One / Two`, `Selected=Yes / No`). Use booleans for parts that come and go (`Show header`, `Show shopper actions`), and text properties for copy that changes per use.
  - **Placement:** place instances, switch variants and properties per frame, and never detach. A change happens once, in the main component.
  - **When copies already exist:** turn them into one component and replace every copy (e.g. 45 `Collection Card / …` frames became `Collection board`).
  - **Record it:** add each new component to the Components table above (id, variants, props, where it's used).

These come from the app code (the source of product truth) and from the user's decisions.
