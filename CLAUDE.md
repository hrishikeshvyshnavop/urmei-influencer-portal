```bash

npm run preview  # Serve the production build locally
```

There is no test runner configured.

## Stack

- **Vite 8** + `@vitejs/plugin-react` — SPA, no SSR/router/framework.
- **React 19** with `StrictMode`. Entry: `src/main.tsx` → mounts `App` into `#root` (`index.html`).
- **TypeScript** in strict mode with `noUnusedLocals`/`noUnusedParameters`. Bundler module resolution; `.tsx` extensions importable.
- **Tailwind CSS v4** via the `@tailwindcss/vite` plugin (not PostCSS). There is no `tailwind.config.js` — theme tokens are defined in CSS.

## Architecture

This is the **URMEI creator portal** — a set of standalone full-screen auth and onboarding screens implemented from Figma. There is no data layer.

- `src/App.tsx` selects a screen from the URL path via `useSyncExternalStore`. There is no router dependency; each `case` renders one screen and passes navigation callbacks down. `src/router.ts` owns routing on the History API: `navigate(path)` (never assign `location.hash` or `location.href` to move between screens), `currentRoute()` (path plus query — the stats pages read `?from=…&via=…`), a document-level click handler that turns same-origin `<a href="/…">` into `navigate()` so plain anchors don't reload, and `upgradeLegacyHashRoute()` so old `/#/route` links still land. Real paths reach the server, so **production hosting must fall back to `index.html`** for unknown paths (Vite's dev and preview servers already do). Routes:
  `/login`, `/apply`, `/apply/form`, `/apply/success`, plus the profile-setup, onboarding, home and shop routes — see the `switch` in `App.tsx` for the current list.
- `src/portal/bank-account.ts` owns the payout record: `PAYMENT_STORAGE_KEY` / `PAYMENT_MESSAGE_TYPE`, `BANK_FIELDS` (the design's bank form schema), and `readBankAccount` / `saveBankAccount`. The account rides inside the same `PAYMENT_STORAGE_KEY` marker `SetupBanner` and `Onboarding` already check, so details typed in setup, in Manage Account, or returned by the provider popup are one record. `readBankAccount` returns `null` for a record with no holder name or account number, which is what makes Manage Account's "bank details not added" state reachable.
- `src/portal/` holds one file per screen. Figma's "filled"/"error" frames are implemented as interactive state inside their screen, not as separate routes.
  - Profile setup is `ReviewDetails` (unnumbered) then four numbered steps: `SetProfilePhoto` (1/4), `FinishProfile` (2/4), `ShippingAddress` (3/4), `BankDetails` (4/4) — `/profile/review`, `/photo`, `/username`, `/shipping`, `/bank`. `Onboarding.tsx` and the `/verify` / `/payment` routes are no longer part of it; identity is verified once, in the apply form (`ApplyCreator` via `identity-verification.ts`), so Manage Account has no Identity section.
  - Sample requests (`sample-requests.ts`, `SampleRequests.tsx`, `SampleRequestDetails.tsx`): a delivered request swaps the cancel panel for a "Write a Review" prompt, and `components/WriteReviewModal.tsx` (Figma `1030:30661`) takes a 1–10 rating, text and up to three photos (scaled down to data URLs). The review is stored per request under `SAMPLE_REVIEWS_KEY` and replaces the prompt with "Your review · n/10"; the rating is kept for the backend to rank top-rated products.
  - `Login.tsx` runs both login steps — enter email, then the one-time code — as internal state. The portal has no passwords: OTP replaced them, which retired `SetPassword`, `ForgotPassword`, `CheckInbox` and `ResetEmail` along with their routes.
- `src/shop/` is the shop experience — My Shop, the catalogue overlay, the storefront and the stats pages. It has its own token vocabulary (`surface-*`, `text-secondary-*`, `border-*`), its own `Button`/`Icon`, and its own router-in-a-prop: `src/App.tsx` renders `shop/App.tsx` for `/shop*` and passes an initial view in (`initialBrowse`, `initialProductId`, …).
  - **"Favorites", not "Featured"** — the feature was renamed throughout, cap 4 (`src/shop/limits.ts`). The persisted `ShopItem.favorite` reads a legacy `featured` key, and the two `product-featured`/`product-unfeatured` activity-log ids keep their old spelling because they are stored values; only their labels changed — and those labels now follow the design's British `favourite` (Figma `1584:96889`), the one place the product spells it that way.
  - The shopper's market is one global value (`portal/country-status.ts`), and `portal/components/CountryModal.tsx` is the only switcher — opened from the header's `LanguageSelector` panel (disabled in the creator portal, where the region belongs to the account) and from the storefront's `NoAvailabilityNotice`, whose "Change Country" button is the shopper's way out of an empty market (Figma `1616:66139`). The notice names that market in its title and drops the button in the creator's own preview (`allowCountryChange`).
  - The storefront's creator card carries the About me strip attached under it (`StorefrontProfileCard`), reading the bio Manage Account saves (`getSavedBio`/`saveBio` in `portal/profile-status.ts`). The old "Read bio" button and its modal are gone.
  - The storefront preview's "<Name>'s Reviews" section (`components/StorefrontReviews.tsx`, Figma `957:29042`) sits between Favorite Picks and All Picks: two review cards per page that slide on paging, each a product header (opens that product) over the creator's verified review — a three-line clamp and up to three photos, in a card fixed at the design's 261px so long reviews never make the section jump. Clicking the review opens `ReviewDetailModal` (Figma `915:28947`) with the full text and date. It is on both the in-app preview and the public `/shop/view` page. There is no review-writing flow for the storefront yet, so `data/reviews.ts` hands out ten placeholder reviews by position (`reviewsForShop`): one per shop product, topped up from the catalogue to `REVIEW_COUNT` (10), none for an empty shop.
  - **Affiliate links come from publishing**: `hasLiveLink(item, publishedAt)` in `data/shop.ts` is the one rule — `publishedAt` is epoch ms (a legacy formatted string self-heals on read) and an item added since the last publish has no link, so the card menu drops its "Copy affiliate link" row and the link rows show "Publish shop to get your product URL".
  - The Search Results filter rail (`components/FiltersSidebar.tsx`, Figma `1594:34810` / `1594:34922`) has six groups in the design's order: Brand, **Commission** (a 0–30% two-handle slider plus the design’s buckets — there is no Price filter), Customer Rating, Category, Ingredients, Country. Category is a department → category tree derived from the catalogue's own `department`/`category` pairs (`CATEGORY_TREE`), and a chip reads "Skincare - Serums"; the design's third level (skin concerns) has no product data behind it. Only one group is open at a time (asked for directly), and a collapsed group shows its applied values as removable chips.
  - `data/stats.ts` is the single source of shop figures: `STAT_SPECS` describes the five metrics (label, formatting, row unit, empty wording, whether a trend line applies) and `statsForProduct` derives numbers deterministically from a product id, so a product reads the same everywhere — the stats row, the product-detail performance card, Home's Top Products and the stat pages all read it — with one row, `statsRowEntries(items, origin)`, shared by Home and My Shop: all five metrics (the two designs each showed a different set; they were unified on request and the product count dropped) (the catalogue's old hardcoded `performance` block is gone).
  - `components/ShopProductCard.tsx` exports `ProductListingCard`, the design's "Featured product listing" — the bordered image + info card with no controls. `ShopProductCard` wraps it with My Shop's click target, overflow menu and favorite-rank footer; the product-stats page renders it bare and with `titleOnly`, the design's brand/name/variant-only variant (`1652:59725`), because that page prints the price, commission and regions in its own column. Change the card here, not per screen.
  - `components/PeriodFilter.tsx` is the only period filter: the stats row on Home and My Shop, the stat pages, product stats and Recent Activities. Its options are `STAT_PERIODS` (Last 7/14/30/90 Days, All Time — Figma `350:44963` in `cehltPtMoGWEtKbF7k3MQQ`, drawn as a radio list sharing `RadioDot` with the sort control). Uncontrolled, it reads and sets the shared stats period (`stats-period.ts`), so a choice made on Home carries into the breakdown pages. Recent Activities passes its own `value`/`onChange`. "All Time" (the default) drops a breakdown's "vs. previous" line.
  - `screens/StatBreakdown.tsx` serves all five metric pages (`/shop/stats/<slug>`) from that config, and `screens/ProductStats.tsx` is one product's Sales/Performance/Details tabs (`/shop/stats/product/<itemId>`) — Sales holds four earnings tiles, Performance two traffic tiles, and Details the selling price and commission per sale above the affiliate link and an "Available in …" line (Figma `1652:59743`). Both are routed by prefix from `src/App.tsx`, outside `shop/App.tsx`, because they are standalone pages rather than shop overlays.
- `src/portal/components/` holds the shared pieces:
  - `PortalLayout.tsx` — sticky side accent panel + header + vertically centred content column. Used by every screen except `ApplyLanding` (no header in the design) and `ApplyCreator` (own scrolling layout).
  - `PortalHeader.tsx` — zero-height `sticky top-0` wrapper so the header overlays the accent photo instead of consuming layout height.
  - `TextField.tsx` — the portal's input (12px padding, body-sm), with optional select, calendar, locked, hint, prefix and required variants.
  - `FieldGrid.tsx` — the shared two-column `FieldSpec` grid used by the apply form, Review Details, the setup steps and the Manage Account modals. Its standing rule is "required and empty"; a screen adds its own rules through `errorFor`. A field with `fullWidth` (in `form-fields.ts`) spans both columns instead of one.
  - `FormModal.tsx` — the 640px centred modal shell Manage Account's Add/Edit address and bank-details forms sit in (Figma `1619:58187` / `1619:59252`): backdrop, scroll-lock, Escape, header with a 40px close button, and a Cancel/submit pair. New account-editing forms belong in this, not in a bespoke overlay.
  - `ActivityRow.tsx` — one row of the Activity Item set (Figma `1584:96889`), drawn by both Home's Recent Activities widget and the full page: 32px `bg-portal-tint` icon well top-aligned with the label, the earnings types' sum set semibold `text-portal-emphasis` beside the label, product name under it and the timestamp on the right. Types, copy and glyphs all live in `shop/activity-log.ts` (`ACTIVITY_LABELS` / `ACTIVITY_ICONS`); `sale`, `commission-confirmed` and `commission-settled` are wired but nothing emits them yet — there is no sales engine, so only add/remove/favourite/publish actually get logged.
  - `NotificationsDrawer.tsx` — the header bell's 440px right drawer (Figma `1619:57134` empty / `1619:57392` with items): date headers, 32px icon wells, unread rows tinted `bg-portal-surface`, and the "No Notifications Yet!" empty state when `groups` is empty. Read state lives in `portal/notification-status.ts`; there is no notification data layer, so `defaultGroups` inside the file *is* the content.
  - `SetupStep.tsx` — chrome for the numbered profile-setup steps (940px column, `n/4` counter, right-aligned Back/primary pair) and the `SETUP_STEP_COUNT` they share.
  - `SearchField.tsx` — the one search box, used by the header, the catalogue, Brands, Sample Requests, Your Reviews, the stat pages and the filter rail's brand search: 40px, the Figma search glyph, a border that darkens when focused or filled, a clear button. Pass `onSubmit` for a submitting `role="search"` form; callers set only the width. Autocomplete lists stay with their screens. Don't hand-roll a search input.
  - `OtpInput.tsx` — the login screen's six code boxes; uncontrolled, cleared by remounting with a new `key`.
  - `ProfilePhotoPicker.tsx` — the one way to set the profile photo, used by setup step 1 and Manage Account: a hidden JPG/PNG input, the `PHOTO_MAX_MB` (2) check, the crop modal (the photo pans in any direction under a fixed 1:1 square the corners resize) and `saveProfilePhoto`. Screens pass a render prop that draws their own trigger and hint and gets `{ pick, error }`; the error replaces the hint. `ProfilePhoto.tsx`'s `CroppedPhoto` draws the saved crop (and the older `offset`/`cropScale` records) at any avatar size. Don't build another upload-and-crop flow.
  - `Checkbox.tsx`, `SocialAccountRow.tsx`.

## Styling conventions

- Global styles live in `src/global.css`, imported once in `main.tsx`. It uses Tailwind v4's `@import "tailwindcss"` and an `@theme` block.
- **Design tokens are defined in `@theme`**, not a JS config, and mirror the Figma library: `--font-sans` (Figtree), the `--color-portal-*` ramp, and a `--text-body-*` / `--text-h*` scale that carries its own line-height. Use the generated utilities (`text-body-sm`, `bg-portal-dark`, `text-portal-muted`) rather than hardcoding hex or px.
- `src/portal/components/Button.tsx` is the shared button, with a typed `variant` system mapped through `variantClasses`. **Add new button styles as a variant here** rather than restyling buttons ad hoc; it spreads native `ButtonHTMLAttributes`. Filled variants carry `border-transparent` so they match the height of outlined ones sitting beside them.
- **Overlay stacking**: the portal's own layers run 40–70 (notifications drawer 40, profile menu 60, `FormModal` and the language modal 70). Radix hard-codes `z-index: 50` on the wrapper it portals every select list, popover and dropdown menu into, so `global.css` lifts `[data-radix-popper-content-wrapper]` to 80 — without it a select opened inside a modal paints behind the panel and reads as a dead control. A `z-*` class on the content itself is inert; the content box is static inside that wrapper.
- Expect rendered boxes to be ~2px taller than the Figma frame where a border is involved: Figma draws strokes inside the frame, CSS borders add to the box.

## Assets

Assets exported from Figma live in `public/urmei/` and are referenced by absolute path (e.g. `src="/urmei/side-panel.jpg"`). Icons are exported SVGs, not hand-written markup — several are raw vector fragments positioned by the percentage insets the Figma output specifies, so keep the nested wrapper spans when copying one.

`public/urmei/apply-hero.png` is the 2.5 MB Figma export used by the apply landing page; convert it to WebP before shipping to production.
